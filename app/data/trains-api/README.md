# Расписание поездов — как это устроено

Перед правками маршрута, табло, `trains-local.json` или `yandex-cloud/` прочитай этот файл целиком.

Яндекс даёт около **500 запросов в сутки**. Табло Ярославского качает **сервер (Yandex Cloud Function)**: ночью по таймеру (`preload_boards`) и **on-demand** при `?board=1`, если даты ещё нет в KV (**только сегодня и будущие**). Приложение табло **только читает** через `?board=1`.

---

## Зачем две разные вещи: табло и нитка

**Табло** — список всех пригородных с Ярославского вокзала на одну дату. По номеру поезда оттуда берём **UID нитки на этот день** (у одного номера в разные дни разные нитки).

**Нитка** (`/thread/`) — остановки, времена, маршрут. Это то, что видит машинист на вкладке «Маршрут».

Приложение никогда не должно само ходить в Яндекс за табло Ярославского. Иначе вечером можно закэшировать «уже есть, но ещё неполное» расписание — и ночная смена «не найдётся» до утра.

---

## Кто сколько платит Яндексу

| Кто | Что делает | Яндекс |
|-----|------------|--------|
| Worker, раз в сутки в **00:05 МСК** | Качает табло Ярославского на **4 даты** | **8–12** запросов `/schedule/` (по 2–3 страницы на дату) |
| Приложение | Читает готовое табло из KV | **0** |
| Приложение, поезда **6000–6999** | Нитка по UID | 1 `/thread/` на поезд×дату, если нет в кэше |
| Приложение, поезда **7000+** | Только `trains-local.json` | **0** |
| Приложение, запасной поиск | Табло **Пушкино**, если номера нет на Ярославском | `/schedule/` через старый прокси |

Нитки в ночную заливку **не входят**.

---

## Ночная заливка (Worker)

Каждую ночь cron `5 21 * * *` UTC (= **00:05 МСК**) берёт календарь **по Москве** и качает ровно четыре дня:

1. сегодня  
2. завтра  
3. послезавтра  
4. сегодня **+6** (горизонт на неделю вперёд)

Для каждой даты: страницы по 1000 строк, пока Яндекс не отдаст хвост. Если строк **нет** — в KV **не пишем** (пустое «готово» нельзя).

Ключи:

| Ключ | Содержимое |
|------|------------|
| `board:s2000002:YYYY-MM-DD` | `{ date, station, fetchedAt, pageCount, schedule }` |
| `board:meta` | какие даты уже залиты (без `kv.list()`) |

Сгорание: **полночь МСК даты + 2 дня** (не «через 24 часа»). Пример: табло на 23.08 живёт до 00:00 МСК **25.08**.

Тот же прогон можно вызвать вручную: `GET ?preload_boards=1&secret=…` (`STATS_SECRET`). Минутный cron `* * * * *` — **только push**, табло с него не качать.

---

## Что делает приложение

Клиент **не** вызывает `?url=` `/schedule/?station=s2000002`. Прокси такие URL режет кодом `USE_BOARD_API`.

Готовое табло: `GET ?board=1&date=YYYY-MM-DD`.

- **200** и непустой `schedule` — пользуемся (`HIT_WORKER_KV` или `MISS_ON_DEMAND_YANDEX` — сервер залил on-demand).
- **404 `BOARD_NOT_READY`** — в KV нет табло и сервер не смог залить (прошлая дата, cooldown, пустой ответ Яндекса). Плашка «Расписание формируется» / «запланировано на …».

Пушкино (`s9600701`) по-прежнему идёт через `?url=` `/schedule/` — это запас, если номера нет на Ярославском.

Нитка: UID с табло → `?url=` `/thread/?uid=…&date=…` → KV по полному URL Яндекса.

---

## Когда приложение вообще ходит в сеть

Только по действию человека:

1. **«Показать маршруты»**  
2. **«Маршрут»** у поездов смены (календарь / профиль)  
3. **«Обновить»** на вкладке маршрута  

Нельзя fetch из секундомера, полночи, `visibilitychange`, свайпов, чипа «84 У». Чип только выбирает день. Поезда грузит кнопка «Маршрут».

## Как ищем поезд 6000–6999

На конкретную дату `YYYY-MM-DD`:

1. **Кэш нитки** `trainThreadsCache[номер@дата]` — есть остановки → сеть не нужна. Пустые записи и `apiOffDay` не считаем попаданием.
2. **Табло Ярославского** — из памяти / localStorage / `?board=1`. Оттуда UID.
3. **Нитка** через Worker (KV, при промахе — Яндекс).
4. **Пушкино** — только если на Ярославском номера нет (без повторного «перекачай табло»).
5. **`trains-local.json`** — короткий офлайн-резерв.

Поезд **не 6000–6999** сразу идёт в `trains-local.json`, без Worker.

UID **не** храним навсегда в `trains-uids.json`. В разные дни у одного номера разные нитки — UID только с табло **этой** даты.

Обычный поиск **не** делает `forceRefresh` табло. Иначе снова получим каскад запросов.

---

## День и ночь

**Дневная смена:** табло на дату смены **D**.

**Ночь:** табло на **D** и **D+1**. Ночные номера ищутся на D, утренние (связка Н→У) — на D+1. Список без повторов: `6256` ночью + `6257`/`6258` утром → `6256 - 6257 - 6258`.

План (`trainPlan`: номер + дата + night/morning) собирается из шаблона смены и передаётся в `getRouteData`.

В 00:00 **ничего не качаем**. Меняется только «рабочая дата» в UI (`#scheduleDateHint`). Обе даты табло уже должны лежать в `stationScheduleCache`.

## Кнопка «Обновить»

| Жест | Что делает | Яндекс `/schedule/` Ярославского |
|------|------------|----------------------------------|
| Короткое нажатие | Только нитки заново (`threadsOnly`), UID из табло в памяти | нет |
| Удержание ~0,6 с | Ещё раз `GET ?board=1` на даты **этой** смены + нитки | нет (только чтение KV) |

Короткое нажатие **не** чистит `stationScheduleCache`. Long-press сбрасывает табло только дат текущей смены, не весь кэш приложения.

---

## Сколько уходит квоты с телефона

| Сценарий | Табло Ярославского | Нитки | Яндекс с клиента |
|----------|--------------------|-------|------------------|
| Три 6000-х, табло уже в KV | `?board=1` | 3 | **3** |
| Ночь: два 6000-х и три 7000-х | `?board=1` | 2 | **2** |
| Короткое «Обновить» | нет | N × 6000-е | **N** |
| Long-press «Обновить» | ещё раз `?board=1` | N | **N** |

Старый антипаттерн: 2 станции × много страниц × каждый поезд × 3 даты — **нельзя**.

## Кэши (не сбрасывать просто так)

| Где | Ключ | Сбрасывать |
|-----|------|------------|
| Нитка, localStorage | `номер@YYYY-MM-DD` | «Обновить», смена даты с force, «Очистить смену» |
| Табло Ярославского | `stationScheduleCache.boards[date]` (макс. 4 даты) | «Очистить смену», long-press по датам смены |
| Индекс UID | `stationUidIndexByDate[date]` | вместе с табло |
| Worker KV, табло | `board:s2000002:дата` | само, в полночь D+2 МСК |
| Worker KV, нитка/Пушкино | `yandex:{полный URL}` | то же правило полуночи |

Пустое табло в localStorage и в KV не кладём.

## Эндпоинты Worker

| Запрос | Смысл |
|--------|-------|
| `GET ?board=1&date=` | Готовое табло. Нет ключа → 404, без Яндекса |
| `GET ?preload_boards=1&secret=` | Тот же прогон, что ночной cron |
| `GET ?url=` `/thread/` | Нитка, KV → Яндекс |
| `GET ?url=` `/schedule/?station=s9600701` | Пушкино |
| `GET ?url=` `/schedule/?station=s2000002` | **400 USE_BOARD_API** |

Заголовки: `HIT_WORKER_KV` | `MISS_YANDEX_API` | `BOARD_NOT_READY`. В квоту Яндекса считается только `MISS_YANDEX_API`.

## Чеклист

- Новый fetch только из трёх кнопок?
- 6000–6999 — нитка через сервер; 7000+ — только локальный файл?
- Сначала кэш `номер@дата` (не `apiOffDay`)?
- UID с табло **этой** даты, не из файла?
- Ярославский только `?board=1`, клиент не бьёт `/schedule/` на `s2000002`?
- Кэш сгорает в полночь D+2 МСК, не TTL 24 ч?
- Пустое табло никуда не пишем?
- Короткое «Обновить» не чистит табло?
- Нет fetch из таймера и полночи?
- Ночной preload и минутный push не смешаны?
