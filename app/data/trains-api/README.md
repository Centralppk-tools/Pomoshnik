# Запросы поездов (Яндекс.Rasp) — ОБЯЗАТЕЛЬНО К ПРОЧТЕНИЮ

> **Лимит: ~500 запросов в сутки.** Любая правка логики поездов в `app/index.html`, `trains-local.json` — **сначала прочитай этот файл целиком.**

---

## Три единственных триггера API

Запрос к Яндексу **только** по явному действию пользователя:

| # | Действие | Функция |
|---|----------|---------|
| 1 | Ввод номеров + **«Показать маршруты»** | `getRouteData()` |
| 2 | **«Маршрут»** у поездов смены (календарь / профиль) | `navigateToRouteWithTrains()` → `getRouteData()` |
| 3 | **«Обновить»** на вкладке маршрута | `refreshRouteData()` → `getRouteData({ threadsOnly: true })` |

**Запрещено** вызывать fetch из:

- `setInterval` / секундомера (`tickScheduleLiveClock`)
- `visibilitychange` / `pageshow`
- полночи (00:00) — только смена «рабочей даты» в UI
- смены вкладок, свайпов, рендера календаря
- chip смены «84 У» (только выбор дня, без API)

Chip «84 У 6:30» **не** грузит поезда. API — только кнопка «Маршрут» у блока «Пoезда» в конструкторе смены.

## Нумерация: кто идёт в API

| Диапазон | Источник | Яндекс API |
|----------|----------|------------|
| **6000–6999** | cache → табло → `/thread/` → `trains-local.json` | **Да** |
| **7000–7999** и любые другие | **только** `trains-local.json` | **Нет** |

**ВНИМАНИЕ:** запросы к Яндекс API разрешены **только** для поездов 6000-й нумерации (6000–6999). Поезда 7000-й нумерации и прочие специфические номера обрабатываются **строго** через `trains-local.json` — без HTTP к Cloudflare Worker / Яндекс.Рasp.

Проверка: `isYandexApiEligibleTrainNumber()` в `app/index.html`. Табло (`/schedule/`) грузится **только** для дат, где есть хотя бы один поезд 6000-й серии.

## Порядок поиска (cache-first + board → uid)

Для поезда **6000–6999** и **конкретной даты** `YYYY-MM-DD`:

1. **`trainThreadsCache`** в localStorage — ключ `номер@дата`. Есть запись с остановками → **0 API**.  
   Записи `apiOffDay` / пустые stops **не** считаются попаданием (чтобы не залипал устаревший UID).
2. **Табло Ярославского** (`s2000002`) на дату — **один раз на дату**, не на поезд:
   - все параллельные поиски ждут один `stationScheduleLoaders[station_date]`
   - из табло берётся **актуальный** `thread.uid` на эту дату → **`/thread/`** (1 API на поезд).
3. **Fallback:** табло Пушкино (`s9600701`) — **только** если на Ярославском нет номера.
4. **Офлайн-резерв:** `trains-local.json` (2 остановки, без API).

Для поезда **7000+** (и вне 6000–6999): сразу `resolveTrainFromLocalOnly()` — **0 API**.

**Статический индекс UID не используется.** Не писать номер→uid вручную в `trains-uids.json` / seed — UID всегда с табло выбранной даты.

## Сколько стоит один сценарий

| Сценарий | Schedule (табло) | Thread (нитка) | Итого |
|----------|------------------|----------------|-------|
| 3 поезда 6000-й серии, табло уже на дату | 0 | 3 | **3** |
| 3 поезда 6000-й серии, первый раз на дату | 1–3 страницы | 3 | **4–6** |
| Ночь: 6670 + 6615 + три 7000 (7733/7734/7738) | 2 | 2 | **~4** |
| Ночь, 5 поездов **все** 6000-й серии, 2 даты | 2–6 | 5 | **7–11** |
| «Обновить» (threadsOnly, табло в памяти) | 0 | N × 6000-серия | **N** |

**Нельзя:** 2 станции × 5 страниц × N поездов × 3 даты (старый антипаттерн).  
**Нельзя:** брать UID «навсегда» из файла — в разные дни у одного номера разные нитки.

## Кэши (не сбрасывать без причины)

| Кэш | Ключ | Когда сбрасывать |
|-----|------|------------------|
| Нитка поезда | `trainThreadsCache[num@date]` | «Обновить», смена даты с force, «Очистить смену» |

Ключ **`номер@YYYY-MM-DD`** — не ломать при миграции. При старте кэш ниток перечитывается из `localStorage` и сразу сохраняется обратно. API вызывается **только если записи нет в кэше** (кроме force refresh).
| Табло станции | `stationScheduleCache.boards[date]` (до 4 дат, Ярославский) | «Очистить смену», full refresh по датам смены |
| Индекс uid на дату | `stationUidIndexByDate[date]` | вместе с табло |

**«Обновить»** — два режима:

| Жест | Действие | API |
|------|----------|-----|
| Короткое нажатие | Только нитки (`threadsOnly`), UID с табло в памяти | N × `/thread/` |
| **Удержание ~0,6 с** | Полное: табло D (+ D+1 ночью) + нитки | schedule + thread |

Полное обновление сбрасывает табло **только для дат текущей смены**, не весь кэш приложения.

## Ночная смена и 00:00

- При открытии маршрута с «Ночь» предзагружаются табло на **D** и **D+1** (один раз каждое).
- План поездов (`trainPlan`: номер + `scheduleDate` + `night`/`morning`) строится из шаблона смены и передаётся в `getRouteData` — без тройного smart-search на поезд.
- **Н + У = общий список:** номера из N и U объединяются без повторов (напр. ночь `6256`, утро `6257`/`6258` → `6256 - 6257 - 6258`); ночные ищутся на D, утренние на D+1.
- **Обе даты табло сохраняются** в `localStorage` (`stationScheduleCache.boards`) — после перезагрузки приложения повторный schedule не нужен.
- Секундомер показывает только время; **рабочая дата** ночной смены (D / D+1) — в `#scheduleDateHint` под часами. **API не вызывается.**
- Та же рабочая дата используется для подсветки карточек и push-уведомлений.
- **`isScheduleContextActive`** — смена «активна» и в D, и в D+1 при включённой «Ночь».
- **API в 00:00 не вызывается.** Данные уже в кэше.
