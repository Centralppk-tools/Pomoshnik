# Метрики
UUID вместо табельного: При первом запуске PWA генерирует случайный device_uuid в localStorage. На Cloudflare Worker для статистики и пушей уходит только этот UUID.

Локальный контур: Табельный номер хранится строго в памяти телефона. Он нужен только для парсинга смен и локальной авторизации. Бэкенд полностью очищен от персональных данных.

# Запросы к API
## ЛОГИКА ФОРМИРОВАНИЯ И КЭШИРОВАНИЯ РАСПИСАНИЯ

1. РАБОТА С UID ПОЕЗДОВ
   • Яндекс API выдает точную нитку остановок строго по уникальному `thread.uid`.
   • Пользователь вводит обычный номер (например, 6256), а приложение запрашивает
     его UID для конкретной даты.

2. СВЯЗУЮЩАЯ БАЗА НА WORKER (ПОЛУЧЕНИЕ UID)
   • Чтобы вытащить UID, Воркер запрашивает суточное табло вокзала (/schedule/).
   • Табло сохраняется в базу KV, а приложение ищет в нем номер поезда и забирает UID.
   • Имея UID, приложение через Воркер запрашивает финальную нитку остановок (/thread/).

3. СРОК ЖИЗНИ КЭША (48 ЧАСОВ / D+2)
   • Все ответы Яндекса (и табло, и нитки) хранятся в KV до 00:00 MSK дня D+2.
   • Это перекрывает ночные смены и защищает от повторных запросов на 2 суток.

4. ОПТИМИЗАЦИЯ И ШИЛДИНГ
   • Поезда 7000+ серии уходят в полный офлайн (запрос идет в локальный trains-local.json).
   • Кэш телефона проверяется первым: если данные уже есть в localStorage, сеть спит.
   • KV — общий кэш: если один машинист скачал табло/нитку, остальные берут ее из KV.
   • Резерв: если 6000-го поезда нет на табло, берется базовая нитка из локального файла.

При клике на «Показать маршруты» данные распределяются по сериям поездов:

Поезда 7000+: Данные берутся из локального файла trains-local.json на телефоне (0% сети, 0% API).

Поезда 6000-й серии: Отрабатывает каскадная схема:

Кэш телефона (localStorage): Если табло вокзала и нитка поезда на эту дату уже скачивались — данные берутся из памяти устройства (0% сети).

Центральная база Cloudflare KV: Если на телефоне пусто, запрос уходит на Worker. Если расписание на эту дату уже было загружено ранее кем-то из других машинистов, Worker мгновенно отдает его из KV (0% запросов к Яндексу).

API Яндекс.Расписания: Самый первый («холодный») старт на конкретную дату. Worker запрашивает табло и нитки у Яндекса, тут же сохраняет их в центральную базу KV для всех пользователей и отдает на телефон.

# WORKER (Хранение)
## СТРУКТУРА ДАННЫХ НА CLOUDFLARE WORKER (KV: TRAIN_CACHE)

┌────────────────────────────────────────────────────────────────────────┐
│ 1. ЦЕНТРАЛЬНЫЙ КЭШ ЯНДЕКС API (ОБЩИЙ ДЛЯ ВСЕХ)                         │
│    • Ключи: yandex:{полный URL запроса}                                │
│    • Суть:  Сырые JSON-ответы (табло вокзалов и нитки 6000-х поездов). │
│             Если один машинист скачал расписание, остальные берут его  │
│             из KV без траты лимитов Яндекса.                           │
├────────────────────────────────────────────────────────────────────────┤
│ 2. ДАННЫЕ ДЛЯ WEB PUSH УВЕДОМЛЕНИЙ                                     │
│    • Подписки:       push_subs:{device_uuid}  (JSON-массив подписок)   │
│    • Задачи:         global_push_jobs         (единый JSON-массив)     │
│    • Ключи дублей:   push_sent:{key}                                   │
│      (Отметки об отправленных пушах, чтобы не спамить экран).          │
│    • Без KV.list() — только get/put (лимит Free list = 1000/день).     │
├────────────────────────────────────────────────────────────────────────┤
│ 3. АНОНИМНАЯ СТАТИСТИКА ДЛЯ СТРАНИЦЫ /STATS                            │
│    • Всего:          stats_total_users        (массив device_uuid)     │
│    • За сегодня:     stats_daily_users:{YYYY_MM_DD}                    │
│      (DAU = length массива; сутки сгорают в полночь MSK).              │
├────────────────────────────────────────────────────────────────────────┤
│ ⚠️ НА СЕРВЕРЕ ПОЛНОСТЬЮ ОТСУТСТВУЮТ:                                  │
│    Табельные номера, ФИО, депо и графики конкретных людей.             │
│    Вся персональная идентификация машиниста заперта на его телефоне.    │
└────────────────────────────────────────────────────────────────────────┘

## КАК РАБОТАЕТ ОБНОВЛЕННЫЙ CLOUDFLARE WORKER

┌────────────────────────────────────────────────────────────────────────┐
│ 1. ЦЕНТРАЛЬНЫЙ КЭШ ЯНДЕКС API (Для расписания)                         │
│    • Пользователь запрашивает расписание на дату.                      │
│    • Воркер делает точечный `.get("yandex:URL")`.                      │
│    • Если данных нет: берет с Яндекса и сохраняет через `.put()`.      │
│    • Расход лимитов: 0 операций list, минимальный расход Яндекса.      │
├────────────────────────────────────────────────────────────────────────┤
│ 2. МЕХАНИЗМ WEB PUSH УВЕДОМЛЕНИЙ (Без сканирования базы)               │
│    • Сохранение смены: все алерты устройства записываются в ОДИН       │
│      общий массив под ключом `global_push_jobs` (через .get / .put).   │
│    • Подписки браузеров: хранятся точечно в `push_subs:{device_uuid}`. │
│    • Ежеминутный Крон:                                                 │
│      1. Раз в минуту делает ВСЕГО ОДИН `.get("global_push_jobs")`.     │
│      2. Находит алерты, которым пора сработать (fireAt <= now).        │
│      3. Забирает подпись из `push_subs:{uuid}` и слать пуш.            │
│      4. Фильтрует массив и перезаписывает его через `.put()`.          │
│    • Результат: 0 операций list! Крон больше не роняет базу.           │
├────────────────────────────────────────────────────────────────────────┤
│ 3. АНОНИМНАЯ СТАТИСТИКА (/stats)                                       │
│    • Пинг с телефона: UUID устройства добавляется в массив текущего    │
│      дня `stats_daily_users:{date}` и общего списка `stats_total_users`│
│      через быстрые точечные `.get()` и `.put()`.                       │
│    • Просмотр /stats: Воркер за 2 быстрых `.get()` считывает длину     │
│      массивов (length) и выводит цифры DAU и Total.                    │ 
├────────────────────────────────────────────────────────────────────────┤
│ ⚡ ИТОГОВЫЙ БАЛАНС ЛИМИТОВ НА БЕСПЛАТНОМ ТАРИФЕ:                      │
│    • Операций `.list()` (Лимит 1 000 / день)   ──► РОВНО 0             │
│    • Операций `.get()`  (Лимит 100 000 / день) ──► ~1 500 (Всего 1.5%) │
│    • Сервер работает бесперебойно 24/7 без ошибок 429.                 │
└────────────────────────────────────────────────────────────────────────┘
